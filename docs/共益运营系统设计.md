# 百里画廊沿线共益运营系统设计

> 目标：把道路节点、公共设施、村集体院落、季节性摊位、民宿导流、寄售交易、
> 志愿班次、就业承诺、生态容量、维修工单和分配结果，全部放进**持续可审计的运营关系**。
> 任何村集体、乡镇或第三方都可以拿同一份事件日志独立复算出同样的结论，
> 不依赖运营商自报。

## 一、年底对账问题与系统机制对照

| 对账时发现的问题 | 系统机制 | 事件/规则 |
|---|---|---|
| 驿站咖啡的收益有数，财政厕所的维修没人认领 | 财政资产入账时即指定首问责任方；故障 72 小时内必须认领，完工时费用逐方分摊且合计必须等于发票额 | `ASSET_REGISTERED` / `REPAIR_OPENED` / `REPAIR_CLAIMED` / `REPAIR_COMPLETED`，违规码 `REPAIR_NEVER_CLAIMED`、`REPAIR_SHARE_MISMATCH` |
| 民宿导流、农产品寄售被运营商混作自己的营业贡献 | 导流必须留凭证并经**实际入住核销**才能计入跨村贡献；寄售货款、佣金、院落使用费在分配结果中逐行标注依据 | `REFERRAL_RECORDED→VERIFIED`、`SERVICE_RECORDED(evidence_refs)`、`BENEFIT_ALLOCATED.lines.basis`，违规码 `CONTRIBUTION_UNVERIFIED_REFERRAL`、`ALLOCATION_UNVERIFIED_REFERRAL` |
| 旺季一过经营者准备带走设备和预付款离场 | 退出请求即时生成**交割清单**（库存、预付款、设备、工单、导流、就业、数据七类责任）；清单确认前一切冻结，全部阻断项凭证据清偿后才允许完成交割 | `OPERATOR_EXITED→HANDOVER_LIST_GENERATED→…→HANDOVER_COMPLETED`，违规码 `EXIT_FREEZE`、`HANDOVER_LIST_TAMPERED`、`HANDOVER_BLOCKED` |
| 经营许可到期沉淀成永久占用 | 许可按资产授权、期限明确；季节性许可 ≤180 天，到期重新竞价/轮换；到期后任何使用记录都判违规；同资产许可不得时间重叠 | `TERM_GRANTED`（信封规则）、`TERM_EXPIRED/REVOKED`、`ASSET_USAGE_RECORDED`，违规码 `USAGE_OUTSIDE_TERM`、`TERM_OVERLAP` |
| 退货、坏账分不清谁承担 | 退货只认批次的**实际供货农户**；坏账按风险来源归责：销售风险/销售方信用只归销售方，只有农户书面自认才能归农户；结算金额按公式强校验 | `CONSIGNMENT_RETURNED/BAD_DEBT/SETTLED`，违规码 `BAD_DEBT_WRONG_PARTY`、`SETTLE_AMOUNT_MISMATCH` |
| 暴雨、检修、超载一刀切，或干脆不处置 | 暂停必须指定**受影响节点 × 受影响业务**两个维度；其他节点、其他业务照常；超载必须先宣布再暂停；解除前逐一核对已入住/已付款旅客承诺已兑现 | `SUSPENSION_ISSUED/LIFTED`、`OVERLOAD_*`、`COMMITMENT_HONORED`，违规码 `SUSPENSION_VIOLATION`、`COMMITMENT_NOT_HONORED`、`LOAD_OVER_CAP_WITHOUT_DECLARATION` |
| 公共资产使用、维修负担、就业兑现、可分配收益混成一锅账 | 季度公示固定四板块分开呈现，且每一项必须能回溯到事件流中的具体事件 | `NOTICE_PUBLISHED`，违规码 `NOTICE_SECTION_MISSING`、`NOTICE_REPAIR_OMITTED`、`NOTICE_PLEDGE_MISMATCH` 等 |

## 二、设计原则

1. **只记事实，不记主张。** 系统里只有“发生了什么”（事件），没有某一方声称的数字。
   分配、公示、交割单都是事件流的派生物，可以随时丢弃重算。
2. **事件流即账本。** `event_id` 全局唯一，`aggregate_id + version` 严格递增，
   重试沿用原事件标识；重放幂等，篡改重放会被 `EVENT_CONFLICT` 捕获。
3. **跨村交换只走四个边界。** `shared_asset`、`operating_term`、
   `community_contribution`、`benefit_distribution` 是村与村、村与运营商之间的
   公共标识，只增不删、不改名（有测试锁定）。村内部经营对象（摊位、寄售、导流……）
   不直接跨村交换，需要结算时通过 `community_contribution` 事件并附证据。
4. **证据先行。** 导流要有核销凭证、贡献要有证据引用、维修完工要有发票、
   就业兑现要有工资表、交割解除要有清偿凭证。无证据的主张不产生任何权利。
5. **金额用整数分（`*_cents`），时间用带时区的 ISO 8601。**

## 三、对象模型（14 类聚合）

| 聚合 | 边界 | 承载内容 |
|---|---|---|
| `shared_asset` | **跨村** | 道路节点、财政厕所、公共设施、集体院落、摊位点位、在场设备；含产权人、资金来源、首问维修责任方 |
| `operating_term` | **跨村** | 驿站/民宿/院落/设施的**有期限**授权、旅客预付款、退出流程 |
| `community_contribution` | **跨村** | 跨村导流、志愿互助等待村际结算的贡献（必须附证据） |
| `benefit_distribution` | **跨村** | 一期可审计分配结果，逐行标注依据与证据 |
| `seasonal_stall` | 村内 | 季节性摊位许可与撤场核验 |
| `consignment` | 村内 | 寄售批次：交付、售出、退货、坏账、结清 |
| `referral` | 村内 | 民宿导流线索、凭证、入住核销 |
| `volunteer_shift` | 村内 | 志愿班次排定、签到、取消 |
| `employment_pledge` | 村内 | 许可附带的岗位/本地用工/最低工资承诺与季度兑现 |
| `eco_capacity` | 村内 | 节点容量核定、承载量上报、超载宣布与解除 |
| `suspension` | 村内 | 暴雨/检修/超载的精准暂停范围与受保护旅客承诺 |
| `repair_order` | 村内 | 故障开单、72 小时认领、完工分摊 |
| `public_notice` | 村内 | 季度公示四板块及来源事件 |
| `handover` | 村内 | 退出交割清单、阻断项清偿、数据移交确认 |

完整字段约束见 `src/catalog.py`（唯一事实来源），
派生产物为 `contracts/domain.schema.json`（`python3 -m src.schema_render` 重新生成）。

## 四、关键审计不变量

审计器（`src/audit.py`）折叠事件流时逐条核对，违规项以稳定违规码返回：

- **许可与占用**：`USAGE_OUTSIDE_TERM`、`USAGE_AFTER_TERM_END`、`TERM_OVERLAP`、
  `ASSET_NOT_IN_TERM`、`SEASON_TOO_LONG`（信封层拦截）。
- **导流证据链**：`CONTRIBUTION_NO_EVIDENCE`、`CONTRIBUTION_UNVERIFIED_REFERRAL`、
  `ALLOCATION_UNVERIFIED_REFERRAL`、`REFERRAL_STATE`。
- **寄售归责**：`CONSIGNMENT_OVERSELL/OVERRETURN`、`BAD_DEBT_WRONG_PARTY`、
  `BAD_DEBT_OVERSIZE`、`SETTLE_AMOUNT_MISMATCH`。结算公式固定为：
  `应付农户 = 销售额 − 佣金 − 农户自认坏账`（销售方坏账不进公式）。
- **精准暂停**：`SUSPENSION_VIOLATION`、`SUSPENSION_BAD_REASON`、
  `COMMITMENT_NOT_HONORED`、`COMMITMENT_NOT_BACKED`、
  `OVERLOAD_WITHOUT_SUSPENSION`、`LOAD_OVER_CAP_WITHOUT_DECLARATION`。
- **维修负担**：`REPAIR_NEVER_CLAIMED`（72 小时）、`REPAIR_UNCLAIMED`、
  `REPAIR_SHARE_MISMATCH`。
- **公示**：`NOTICE_SECTION_MISSING`、`NOTICE_REPAIR_OMITTED`、
  `NOTICE_PLEDGE_OMITTED/MISMATCH`、`NOTICE_ALLOCATION_MISMATCH`、
  `NOTICE_USAGE_OMITTED`、`NOTICE_BAD_SOURCE`。
- **退出交割**：`EXIT_FREEZE`、`EQUIPMENT_NOT_LISTED`、`HANDOVER_NO_EXIT`、
  `HANDOVER_LIST_TAMPERED`、`BLOCKER_NOT_CLEARED`、`HANDOVER_BLOCKED`、
  `DATA_NOT_HANDED_OVER`。
- **流完整性**：`VERSION_GAP`、`EVENT_CONFLICT`。

## 五、关键流程

### 5.1 季节许可（不沉淀）

公开竞价/轮换 → `TERM_GRANTED`（`seasonal=true`，≤180 天，列明资产）
→ 旺季内逐笔经营 → `TERM_EXPIRED` 或到期自然失效
→ 院落 `ASSET_RETURNED`、摊位 `STALL_CLOSED` 核验 → 下一季重新竞价。

许可只授予资产使用权，不改变产权：财政厕所始终是 `owner=government`、
集体院落始终是 `owner=collective`，运营商自带设备登记为
`owner=operator, removable=true` 并挂在 `present_at_asset_id` 点位上。

### 5.2 寄售与坏账

`CONSIGNMENT_DELIVERED`（农户/销售方/未售策略写进批次）
→ 多笔 `CONSIGNMENT_SOLD`（库存数量强校验）
→ 未售 `CONSIGNMENT_RETURNED` 退回农户
→ 坏账 `CONSIGNMENT_BAD_DEBT` 按 `basis` 归责
→ `CONSIGNMENT_SETTLED` 按公式校验实付。
退出时未结清批次自动进入交割清单，库存不允许带离合同期。

### 5.3 导流证据链

台卡二维码/预约码登记线索（`REFERRAL_RECORDED`）
→ 承接方办理入住后核销（`REFERRAL_VERIFIED`，带 booking 与 checked-in 时间）
→ 村际结算只引用已核销线索（`SERVICE_RECORDED.evidence_refs`）
→ 分配行以 `basis=referral_commission` 入账。
重复、伪造、未入住的线索走 `REFERRAL_REJECTED`，退出时仍未核销的按驳回处理。

### 5.4 精准暂停与旅客承诺

`SUSPENSION_ISSUED` 必填两组维度：`scope_asset_ids`（哪些节点/点位）
× `service_kinds`（`new_booking / stall_sale / traffic_entry /
consignment_sale / new_referral` 中哪些业务）。
- 暂停窗口内，落在“节点×业务”交集上的新业务一律判 `SUSPENSION_VIOLATION`；
- `protected_commitments` 显式登记已入住/已付款旅客及安排（改期、续住、退款）；
- 每一条承诺由 `COMMITMENT_HONORED` 核销，且对应预付款必须已履约或退款；
- 全部承诺兑现后才允许 `SUSPENSION_LIFTED`。

超载路径：`LOAD_REPORTED` 超容量 → 当日必须 `OVERLOAD_DECLARED`
→ 发出 `reason=overload` 的暂停 → `SUSPENSION_LIFTED` → `OVERLOAD_CLEARED`。
只上报不处置、宣布超载却不暂停，均为违规。

### 5.5 维修工单与财政资产

任何故障先 `REPAIR_OPENED`（自动算 72 小时认领期限）→
`REPAIR_CLAIMED` 记录责任与依据（如许可条件中的首问条款）→
`REPAIR_COMPLETED` 记录费用、逐方分摊（合计必须等于费用）与发票。
财政资金修建的厕所不因“公家的东西”而悬空：资产登记时的首问责任方、
许可条件、村集体兜底三条路径必须有一条落实。

### 5.6 季度公示（四板块分开）

`NOTICE_PUBLISHED.sections` 固定为：

1. `asset_usage`：每个许可对公共资产的实际使用（谁、用了什么、什么时间）；
2. `repair_burden`：每张工单的故障、认领方、费用、分摊明细；
3. `employment`：每个许可承诺岗位/本地用工数与工资凭证兑现数；
4. `distributable_benefit`：可分配收益总额、兑付状态、逐行依据。

审计器自动比对：本村本季工单不得遗漏、就业数字必须与工资凭证投影一致、
分配总额与兑付状态必须与 `benefit_distribution` 事件一致、
每个许可都必须出现在使用板块，且 `source_event_ids` 必须逐笔存在。

### 5.7 退出交割

```
OPERATOR_EXITED（退出请求）
   └─ 系统即时快照 pending 清单，设备/货物/新收款即刻冻结
HANDOVER_LIST_GENERATED（发布清单，与系统快照逐项比对，防删改）
   ├─ B-inv-* 未结清寄售：结清或退货
   ├─ B-pay-* 未结合同预付款：履约或退款
   ├─ B-eqp-* 在场设备：公共资产交还 / 自有设备登记放行
   ├─ B-rep-* 未完工单：完工并分摊
   ├─ B-ref-* 未核销导流：核销或驳回
   ├─ B-plt-* 就业承诺：提交工资凭证、补足缺口
   └─ B-dat-* 数据责任：移交或销毁确认
HANDOVER_BLOCKER_RESOLVED × N（每项凭证据解除，审计器核对事实确实清偿）
HANDOVER_COMPLETED（仍有未清偿项则 HANDOVER_BLOCKED；无数据确认则
                    DATA_NOT_HANDED_OVER）
```

清单由系统从事件投影生成（`src/handover.py`），运营商只能确认不能编辑；
发布的清单与快照不一致即 `HANDOVER_LIST_TAMPERED`。

## 六、运行与独立审计

```bash
python3 -m unittest discover -s tests     # 34 项契约/审计/交割测试
python3 -m src.schema_render              # 从目录重新生成 JSON 契约
python3 -m src.scenarios                  # 导出合规全季样例
python3 -m src.report data/sample_season.json   # 任意一方独立复算
```

合规全季样例 `data/sample_season.json`（55 个事件）演示了一个完整旺季：
资产登记 → 竞价许可与就业承诺 → 寄售/导流/志愿 → 暴雨与超载两次精准暂停
（在住与已付款旅客承诺均兑现）→ 财政厕所 72 小时内认领分摊 →
寄售按公式结清（销售方坏账不扣农户）→ 季度四板块公示 →
退出即出交割清单、逐项清偿后完成交割。
